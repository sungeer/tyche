> 面向银行投资理财部的 AI 投顾 Agent，基于现有 Starlette 后端扩展。

## 一、你已经有什么

现有后端基础设施已完整：JWT 认证、领域分层结构（domains/）、MySQL 异步访问、Huey 任务队列。

## 二、为什么选 LangGraph 而不是其他方案

### 方案 A：纯 Prompt（最简单，但不能用）

```
System Prompt 里写："你必须先检查客户风险等级，不得推荐不匹配的产品"
```

**问题**：
- 大模型可能"忘记"遵守，无法 100% 保证
- 无法产生可被监管追踪的审计记录
- 换一种提问方式可能绕过限制

### 方案 B：LangChain AgentExecutor（老方式，不推荐）

```
while True:
    让大模型决定下一步
    执行工具
    if 大模型说完了: break
```

**问题**：大模型可以随时直接输出建议，合规检查工具可以被跳过。

### 方案 C：LangGraph（推荐）

把流程画成一张图，大模型必须按图走：

```
用户输入
  ↓
收集客户信息（查风险等级、查持仓）
  ↓
大模型生成候选产品
  ↓
[合规检查节点] ← 硬编码在图里，任何路径都绕不过去
  ↓
  ├── 通过 → 生成推荐建议 + 附加风险提示
  └── 不通过 → 向客户说明原因，推荐替代产品
  ↓
[审计日志节点] ← 所有路径都经过
  ↓
输出
```

**关键优势：合规逻辑是图的结构，不是 Prompt 里的文字描述，大模型改不了它。**

## 三、整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                   Starlette HTTP 请求                        │
│  POST /api/v1/agent/stream  (JWT 认证，Bearer token)        │
└────────────────────────┬────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────┐
│             src/domains/agent/（新增 domain）                │
│                                                              │
│   views.py      ← HTTP 入口，返回 SSE 流式响应               │
│   service.py    ← 调用 LangGraph graph                       │
│   graph.py      ← LangGraph 状态机定义（核心）               │
│   callbacks.py  ← 审计/合规 Callback                         │
│   tools/        ← 工具清单（见 02-tool-catalog.md）          │
└─────────────────────────────────────────────────────────────┘
                         │
          ┌──────────────┼──────────────────┐
          ▼              ▼                  ▼
    [工具层]         [LLM 层]          [存储层]
    金融数据查询      Claude API         MySQL（对话/审计）
    知识库 RAG       （Anthropic）       Chroma（向量库）
    合规规则引擎
```

---

## 四、技术选型

| 决策项 | 选择 | 原因 |
|--------|------|------|
| Agent 框架 | LangGraph | 状态机强制合规流程，金融场景必须 |
| LLM | Claude 3.5 Sonnet | 工具调用稳定，中文能力好 |
| RAG 向量库 | Chroma | 最轻量，适合起步，纯 Python |
| 流式输出 | SSE | Starlette 原生支持，前端简单 |
| 审计存储 | MySQL（现有） | 和现有架构一致，无需引入新存储 |
